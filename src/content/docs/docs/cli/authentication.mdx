The `prb auth` commands manage authentication credentials for the Probo CLI. You need to authenticate before using any other commands.

Login uses OAuth 2.0 **device authorization**: the CLI opens (or prints) a browser URL, you approve access, and the CLI stores the resulting tokens locally. You do not paste an API token into `prb auth login`.

## Login

<Steps>

1. **Run the login command**

   ```bash
   prb auth login
   ```

   In interactive mode, you'll be prompted to choose where your account is hosted:

   - **Probo US** — `us.probo.com`
   - **Probo EU** — `eu.probo.com`
   - **Other** — your self-hosted hostname (e.g. `probo.example.com`)

2. **Approve access in the browser**

   The CLI prints a verification URL and one-time code, and opens the browser when possible. Complete the authorization flow, then return to the terminal.

3. **Pick a default organization** (optional)

   After authorization, interactive mode can set a default organization for subsequent commands.

</Steps>

### Non-interactive examples

```bash
# Probo US
prb auth login --hostname us.probo.com

# Probo EU
prb auth login --hostname eu.probo.com

# Self-hosted
prb auth login --hostname probo.example.com --org YOUR_ORG_ID
```

### Flags

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--hostname` | Interactive region picker (falls back to `eu.probo.com` when non-interactive and unset) | Probo hostname, e.g. `us.probo.com`, `eu.probo.com`, or a custom host |
| `--org` | — | Default organization ID to store with the host credentials |

## Check status

View authentication status for all configured hosts:

```bash
prb auth status
```

This displays the active host, token validity, and selected organization.

## Logout

Remove stored credentials for a host:

```bash
prb auth logout
```

In interactive mode, you can select which host to log out of when multiple hosts are configured.

### Flags

| Flag | Description |
| ---- | ----------- |
| `--hostname` | Specific host to log out of |

## API tokens for automation

For scripts and CI that should not use device login, create a personal API token in the console under **Settings → API Tokens** (or `/me/oauth-tokens`) and pass it to tools that accept Bearer tokens (MCP, n8n, custom HTTP clients). The CLI login flow itself does not accept `--token`.
