This document provides a comprehensive reference for environment variables used by **`probod-bootstrap`** (invoked by the Docker entrypoint) to generate the YAML configuration file for `probod`.

Unless noted otherwise, variables use the `PROBOD_` prefix (for example `PROBOD_API_ADDR`). See `.env.example` in the Probo repository for the full list, including connectors and agent settings.

## How It Works

When running Probo in Docker:

1. **With `PROBOD_ENCRYPTION_KEY` set**: The entrypoint always regenerates `/etc/probod/config.yml` from `PROBOD_*` environment variables via `probod-bootstrap`
2. **Without `PROBOD_ENCRYPTION_KEY`**: An existing mounted config file is used as-is
3. **Direct `probod` usage**: The `probod` binary only accepts YAML configuration files via the `-cfg-file` flag

## Security Best Practices

### Required Secrets

The following environment variables are **required** and must be set to secure random values in production:

1. `PROBOD_ENCRYPTION_KEY` - Generate with: `openssl rand -base64 32`
2. `PROBOD_AUTH_COOKIE_SECRET` - Generate with: `openssl rand -base64 32`
3. `PROBOD_AUTH_PASSWORD_PEPPER` - Generate with: `openssl rand -base64 32`
4. `PROBOD_OAUTH2_SERVER_SIGNING_KEY` - Generate as a PEM RSA private key

### Secret Generation Example

```bash
# Generate all required secrets
export PROBOD_ENCRYPTION_KEY=$(openssl rand -base64 32)
export PROBOD_AUTH_COOKIE_SECRET=$(openssl rand -base64 32)
export PROBOD_AUTH_PASSWORD_PEPPER=$(openssl rand -base64 32)
export PROBOD_OAUTH2_SERVER_SIGNING_KEY="$(openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048)"

echo "PROBOD_ENCRYPTION_KEY=$PROBOD_ENCRYPTION_KEY"
echo "PROBOD_AUTH_COOKIE_SECRET=$PROBOD_AUTH_COOKIE_SECRET"
echo "PROBOD_AUTH_PASSWORD_PEPPER=$PROBOD_AUTH_PASSWORD_PEPPER"
echo "PROBOD_OAUTH2_SERVER_SIGNING_KEY is set (PEM key hidden)"
```

## Docker Configuration Priority

The **Docker entrypoint script** follows this priority order:

1. If `PROBOD_ENCRYPTION_KEY` is set, regenerate the config file from `PROBOD_*` environment variables (even when a stale file exists on a volume)
2. Otherwise, if `CONFIG_FILE` exists (e.g., mounted from ConfigMap/volume), use it as-is
3. Otherwise, fail — encryption key unset and no config file available

## For Non-Docker Deployments

If you're running `probod` directly outside of Docker, you must provide a YAML configuration file:

```bash
probod -cfg-file /path/to/your/config.yaml
```

See the [Config File](/docs/configuration/config-file) for the complete YAML configuration format and examples.
