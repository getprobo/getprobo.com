# Contributing

## Local development

Use Node.js 24 and install the locked dependencies:

```bash
npm ci
npm run dev
```

The site is available at [http://localhost:4321](http://localhost:4321).

## Documentation

Documentation pages live in `src/content/docs/docs/`. Every MDX file must include a `title` and `description` in its frontmatter.

- Write for a reader with a specific goal. Lead with what the feature or record is for, then explain its model, lifecycle, boundaries, and related interfaces.
- Use plain, direct language and the terminology shown by the current product. Distinguish Probo API keys, OAuth credentials, SCIM tokens, and third-party credentials.
- Verify behavior against the Probo repository. Prefer end-to-end tests, public GraphQL schemas, MCP and CLI definitions, and configuration code over README or marketing claims.
- State limitations and security implications where they affect a reader's decision. Do not promise legal compliance or describe a generated or inferred result as authoritative.
- Use realistic examples without real customer data, secrets, or placeholders that make a command unsafe to copy.
- Add navigable pages to `src/lib/docs-sidebar.ts` and assign the group to a section in `src/lib/docs-navigation.ts`.
- Use root-relative links such as `/docs/product/getting-started/quickstart`.
- Prefix templates and unpublished support files with `_`; Starlight excludes them from the build.
- Put access-review screenshots in `public/docs/access-review/` and follow its `README.md`.
- Test commands and configuration examples against the supported product version.
- Prefer Starlight components such as `Steps`, `LinkCard`, and asides over custom markup.

## Quality checks

Run the same checks as pull-request CI:

```bash
npm run format
npm run check:docs
npm run build
```

The format command only touches changed file types that Prettier can parse reliably. Review MDX changes manually.

`npm run check:docs` validates frontmatter, internal documentation links, sidebar routes, and referenced public assets.

## Generated developer reference

The exhaustive MCP tool, n8n resource, and CLI command indexes are generated from a local checkout of the Probo repository:

```bash
npm run docs:generate
npm run docs:check-reference
```

The generator uses `../probo-merge` by default. Set `PROBO_REPO_PATH` when the checkout is elsewhere. Commit generated MDX, and do not edit files marked as generated by hand.
